## 検討したこと
ストーリー6の「行きたい数」を何で数えるか。あわせて、Visit があるスポットを削除するときの扱い。

## 検討した選択肢
### 行きたい数
- A: status が want_to_go のレコード数だけ数える
- B: want_to_go と visited の合計を数える（＝一度でも「行きたい」に登録した人数）

### Visit があるスポットの削除
- C: dependent: :destroy（スポットと一緒に Visit も消す）
- D: dependent: :restrict_with_error（Visit があるスポットは削除させない）

## 決定・理由
- 行きたい数は B を採用。「行きたい → 訪問済み」は同じレコードを更新する設計のため、A だと訪問した人ほど行きたい数から消え、県が知りたい「興味を持った人の数」を少なく見せてしまう。
  - ただし「行きたい」を経ずに直接チェックインした人も B に含まれる点は割り切る。
- 削除は D を採用。C だと、スポットを消したときに訪問の記録（県にとっての成果データ）も消えてしまう。D なら destroy が false を返すので、#7 で入れた if/else で一覧にエラーを出せる。

## 集計の方法
Visit.group(:spot_id, :status).count で、スポットの件数にかかわらず1回のクエリで集計する（N+1 にならない）。Visit がないスポットは nil になるので .to_i で 0 と表示する。
